# Profile Router 界面设计稿（纸面，v0.2）

> 先定逻辑，再改代码。本稿里标 ❓ 的地方需要你拍板。

## 1. 现在的界面哪里不对（自查）

1. **概念太多，用户要自己想清楚三层关系。** 现在有「网站」「账号」「浏览器用户」「浏览器」「链接规则」五个东西，用户要先懂"账号登录在哪个浏览器用户里"才能用。可你要的核心只是：**切换某个网站的账号**。
2. **同一件事有两条路。** 「＋ 添加账号」（把账号挂到已有用户）和「新建用户」（建用户、顺便挂账号）做的是同一个目标，入口却分开。
3. **三种排列只是换个角度看同一批数据，但每种视图能做的操作不一样**（按网站能加分类，按用户能"打开用户"），切视图后操作就变了。
4. **高级功能和日常功能混在一起。** 链接规则、设为默认浏览器、新建用户都和"切换账号"并排放在底部。
5. **"浏览器用户"是技术细节，却是主角之一。** 用户关心的是"X 小号"，不是"Chrome · Profile 2"。

## 2. 先定一个根本问题 ❓

一个浏览器用户里放什么？两种模型：

| | A. 一个账号 = 一个浏览器用户 | B. 一个"房间" = 一个浏览器用户 |
|---|---|---|
| 例子 | X 主号、X 小号、B站大会员各自一个浏览器用户 | 「主房间」里登录 X 主号 + B站大会员 + PSN 日服；「小号房间」里登录 X 小号 + PSN 港服 |
| 优点 | 最简单：加账号＝自动新建一个干净用户，用户完全不用管"浏览器用户" | 用户数量少；同一房间下各网站账号互相关联（同一个人设） |
| 缺点 | 账号多了浏览器用户也多（每个都要装一次 LastPass） | 加账号时要选"放进哪个房间"，多一步思考 |
| 和你之前说的 | 「点击后切换到 X 账号2，直接打开第二个浏览器用户」 | 「账号2」像一个人设，跨网站使用 |

**已定：B（按"人"分房间）。** 原建议：B 为主，A 是它的特例——新建房间时如果只放一个账号，就等于 A。界面上把"浏览器用户"叫做**房间**，隐藏 Profile 编号。

以下按 B 设计；如果你选 A，第 3 节的「房间」一栏会消失，其余不变。

## 3. 信息结构

```
网站（x.com，带图标）
 └─ 账号（主号 / 小号 …）── 登录在 ──> 房间（= 一个浏览器用户，有名字、颜色、所属浏览器）
```

- 主角：**网站 + 账号**。主窗口只围绕它。
- 配角：**房间**。在"添加账号"时选一下；在第二页「房间」里集中查看和管理。
- 后台：浏览器、Profile 编号、链接规则、默认浏览器 → 全部放进「设置」。

## 4. 主窗口：两个页面，以账号为主导

顶部两个页签：**[账号]**（默认，按网站排）和 **[房间]**（第二页）。

### 4.1 「账号」页（默认）

```
┌──────────────────────────────────────────────────────────┐
│ [账号] [房间]    🔍 搜索网站或账号 / 粘贴网址…      [⚙ 设置] │
├──────────────────────────────────────────────────────────┤
│ [X]  x.com            ● 主号   ● 小号   ● 工作号     [＋] │
│ [b]  bilibili.com     ● 大会员 ● 追番号              [＋] │
│ [PS] playstation.com  ● 日服   ● 港服                [＋] │
│ [GH] github.com       （还没有账号）                 [＋] │
├──────────────────────────────────────────────────────────┤
│ [＋ 添加网站]                                             │
└──────────────────────────────────────────────────────────┘
  ● = 房间的颜色（同一房间的账号同色）
```

- **点账号** → 用对应房间打开这个网站（就是"切换账号"）。
- **右键账号** → 编辑 / 移到别的房间 / 删除。
- **[＋]** → 给这个网站添加账号（见第 5 节）。
- **搜索框**：输入字过滤网站和账号；粘贴网址回车 → 按"网站有几个账号"直接打开或弹出选择。
- 去掉"按浏览器"排列；浏览器只是房间的一个属性，在「房间」页显示。

### 4.2 「房间」页（第二页）

```
┌──────────────────────────────────────────────────────────┐
│ [账号] [房间]                                     [⚙ 设置] │
├──────────────────────────────────────────────────────────┤
│ ● 我        Chrome   [X] 主号  [b] 大会员  [PS] 日服   [打开] │
│ ● 小号      Chrome   [X] 小号  [PS] 港服              [打开] │
│ ● 工作      Iron     （还没有账号）                    [打开] │
│ ● 测试      Edge     （还没有账号）                    [打开] │
├──────────────────────────────────────────────────────────┤
│ [＋ 新建房间]                                             │
└──────────────────────────────────────────────────────────┘
```

- 每行一个房间：颜色、名字、浏览器、里面登录的账号（带网站图标）。
- **点账号** → 同「账号」页，切到这个账号。**[打开]** → 只打开这个房间（不指定网站）。
- **右键房间** → 改名 / 改颜色 / 复制扩展到这个房间 / 删除（只删登记，不删浏览器里的用户）。
- **[＋ 新建房间]** → 静默建本地浏览器用户，可勾选扩展（同第 5 节的"新建房间"）。
- 你电脑上已有的浏览器用户**自动列为房间**（名字沿用浏览器里的名字，可改）。

## 5. 添加账号（唯一入口，一个窗口完成）

```
┌ 给 x.com 添加账号 ─────────────────────────────┐
│ 账号名：[ 小号            ]                      │
│                                                  │
│ 放在哪个房间里：                                  │
│   ( ) 主房间        ← 已有：B站大会员、PSN 日服    │
│   ( ) 工作          ← 已有：GitHub                │
│   (•) 新建房间：[ 小号      ]  浏览器 [Chrome ▾]  │
│         扩展：☑ LastPass  ☐ 篡改猴  … [从主房间复制] │
│                                                  │
│                        [取消]  [添加并打开登录页] │
└──────────────────────────────────────────────────┘
```

- 选「新建房间」= 静默建本地浏览器用户（不弹浏览器登录/设置页），打开扩展商店页和网站。
- 已有房间里**已经有同网站的账号**时，该房间置灰并提示"已登录 x.com 主号，同一房间不能放同网站两个账号"——这条规则防止切换错号。
- 点「添加并打开登录页」后，主窗口出现这个账号；你在打开的网页里用 LastPass / passkey 登录一次即可。

## 6. 设置窗口（低频，全部收进来）

| 页 | 内容 |
|---|---|
| 链接 | 设为默认浏览器；没有账号的网站怎么打开（弹窗选 / 固定用某个房间）；规则列表 |
| 扩展 | 新建房间时默认装哪些扩展 |
| 关于 | 版本、配置文件位置 |

## 7. 首次打开（空状态）

```
还没有账号。
① 添加一个网站（输入 x.com）
② 给它加账号：选"新建房间"，在打开的页面登录
你电脑上已有的浏览器用户已经列在「房间」页里，可以直接往里登记账号。
```

## 8. 已定（2026-10-30）

1. 一个房间 = 一个浏览器用户，按"人"分；同一房间里同一网站只放一个账号。
2. 主窗口以账号为主导：默认「账号」页按网站排；「房间」是第二页；不要"按浏览器"排列。
3. 已有的浏览器用户自动当成房间。
